# 零基础吃透这个项目：按实验推进

目标是能说明、预测、运行并验证项目的行为。衡量标准不是记住了多少术语，而是能否指出输入进入哪个函数、状态怎样变化、结果是否合理，以及模型哪里不适用。

这条路线绑定当前仓库。进度保存在 [LEARNING_PROGRESS.zh-CN.md](LEARNING_PROGRESS.zh-CN.md)，不要让聊天记录成为唯一记忆。代码修复与学习进度是两回事：测试通过不代表你已经理解。

## 先固定学习方式

每次只处理一个可验证的问题，每次约 30–60 分钟。按下面顺序进行：

1. 用自己的话写下问题，例如“车辆松油门后为什么应该减速？”
2. 找到一个相关函数，圈出输入、输出和单位。
3. 运行前先预测正负、大小或变化趋势。
4. 做最小实验，只改变一个输入。
5. 用实际输出解释预测对错，再看对应测试如何判定。
6. 合上 AI 的解释，用自己的话复述，然后记录证据和下一步。

第一轮允许暂时把复杂函数当成黑盒，但必须知道它吃什么输入、吐什么输出。之后沿着一次真实调用逐层打开它。

## 学习顺序及过关标准

### 0. 学会运行一个函数

只补 Python 的变量、函数、参数、返回值、条件、循环、列表/字典、导入。类先理解成“装着一辆车参数的对象”；暂缓继承、装饰器、异步等话题。

安装和测试从仓库根目录运行：

```bash
python -m pip install -e ".[test]"
python -m pytest tests/test_dynamics_regressions.py -q
```

如果本机没有 Python，请让 AI 先确认操作系统和解释器路径，再给安装步骤；不要盲目复制别人的环境路径。本次交付使用的是工作目录中的独立依赖，不是你系统里已经配置好的学习环境。

过关：能说明 `Vehicle("demo", 1500, 100)` 中三个参数分别代表什么；能运行一个测试，并区分“代码报错”和“断言不通过”。

### 1. 松油门为什么减速

代码锚点：`vehicle.py` 的 `Vehicle`、`calc_resistance`、`calc_acceleration`。测试锚点：`test_coasting_obeys_force_balance`。

```bash
python -c "from vehicle_dynamics_toolkit.vehicle import Vehicle,calc_acceleration; car=Vehicle('demo',1500,100); print(calc_acceleration(car,20,throttle=0))"
```

只学质量、力、速度、加速度及它们的单位；理解 `(驱动力-阻力)/质量`。这里 20 是 m/s，等于 72 km/h。

实验：比较 10、20、30 m/s 时松油门的加速度，先预测符号。再把质量从 1500 改为 2000，解释为什么结果不能简单认为“所有项都减少四分之一”：滚阻本身也随质量变化。

过关：能解释为什么旧版 `max(0, acceleration)` 会掩盖滑行减速，以及为何静止时又需要防止阻力造成倒车。

### 2. 从油门一路追踪到车速

调用主线：`simulate_acceleration` → `calc_acceleration` → `calc_wheel_force` → `get_engine_torque`。

本阶段再学扭矩、转速、挡位速比、传动效率、轮胎半径；不要一次读完整发动机理论。

实验：同一速度下比较半油门/全油门；同一车辆比较两种质量；查看加速结果的首个样本和 `reached_target`。用扭矩很小的车辆触发超时。

过关：能写出“发动机扭矩 × 挡位速比 × 主减速比 × 效率 ÷ 轮胎半径 = 驱动力”；解释为什么从 5.4 km/h 开始不能叫完整的 0–100。

### 3. 理解仿真是如何一步步推进的

代码锚点：`_advance_speed`、`simulate_acceleration`。先学时间步长 dt，再学数值积分；积分先理解为“小步累计变化”，不要求一开始推导高等数学。

实验：初速度 1 m/s、加速度 −2 m/s²、步长 1 s。手算 0.5 s 后停车、移动 0.25 m，再与函数输出对照。解释剩余 0.5 s 为什么不能继续倒退。

过关：区分“t=0 的初始状态”和“推进一步后的状态”；知道更小 dt 通常会减少离散误差，但不能修复错误的物理公式。

### 4. ACC：把控制器和车辆分开理解

代码锚点：`idm_acceleration` → `_following_history` → `acc_simulation`。测试锚点：`test_acc_has_true_initial_sample_and_physical_actuator_limits`。

先区分三个量：当前自车速度、前车速度、自己想达到的巡航速度。IDM 根据速度和间距提出加速度要求；执行器限制实际能加速/制动多少。

实验：保持巡航目标 80 km/h，分别让前车静止、慢行、加速；再把初始间距从 40 m 改成 1 m。观察加速度、间距及 `collision_s`，不要只看终点车速。

过关：解释旧版巨额减速度从哪个分母产生；解释“舒适减速度参数”“实际最大制动力”和“保证不碰撞”是不同概念。

### 5. 横向：只先研究一个小角度转弯

代码锚点：`calc_steady_state_cornering`、`simulate_step_steer`。先用线性轮胎，再看 Pacejka。

这一阶段只学前轮转角、侧偏角、侧向力、横摆角速度。自行车模型是把每根车轴的左右轮合并理解，并不是模拟两轮自行车。

实验：同一车速，分别输入 +3° 和 −3°；半径大小应相同，横摆方向相反。再比较刚开始转向和稳定转向的侧向加速度。

过关：能说明代码里的转角是前轮角，而非方向盘角；能解释 `ay = dvy/dt + vx*r` 中为什么稳态时可以少一项、瞬态时不能。

再学 Pacejka 时，先只比较“小角度近似线性、大角度趋于饱和”。B/C/D/E 的完整拟合理论进入待学列表，不阻断当前主线。

### 6. 用两种语言验证同一个行为

代码锚点：`simulation.py`、`scripts/compare_py_cpp.py`、`ros2_ws/src/vehicle_dynamics_node/src/dynamics_runner.cpp`、`dynamics.hpp`。先把 C++ 当作另一种表达相同运算的方法。

先运行 `python scripts/compare_py_cpp.py --generate`，阅读 `build/parity/inputs.csv` 的前几行，再运行完整 `--check`（需 C++17 编译器）。

实验：复制输出 CSV，在副本中把一个车速改大，使用 `--compare` 检查。预期失败，并找到报告中的工况、步数和字段。只改实验副本，不改基准和正式测试来“凑通过”。

过关：能区分相对误差和绝对误差；能解释“Python/C++ 一致”为什么不等于“与实车一致”。

### 7. 最后接上 CAN、UDS、ROS2、FMU

按实际数据流逐个学习，不同时开四条线：

- CAN：追踪一个车速值从 `CoreECU.speed` 到 CAN 字节，再解码回来；先学信号、字节和缩放，再学字节序/DBC。
- UDS：只追踪一次读车速请求；解释请求字节、DID 和响应值，再学会话与安全访问。
- ROS2：追踪 `/vehicle/control` 到 `Model.step()` 再到 `/vehicle/state`；这时才学习节点、话题、发布和订阅。
- FMU：阅读 `ecu_fmu.c`，指出它与整车模型目前有哪些不同；不要误以为所有入口已使用统一物理模型。

过关：能画出一条具体数据流，并准确指出当前模块哪里相连、哪里仍各自运行。

## 遇到陌生名词时的规则

让 AI 每次最多解释三个阻碍当前实验的名词。每个解释必须包含：一句白话、项目中的文件/函数、一个带单位的例子、它会影响哪个输出。

暂时不影响当前实验的名词放进进度文件“待学词”，记录回到哪一阶段再学。例如第一阶段遇到 ROS2、ISO-TP、FMU，可以先记下，不开始新教程。类比只是入口，最终要回到代码或公式。

如果 AI 的回答出现五六个新词，直接要求：“先停止扩展，只解释完成当前实验必须理解的那个词。”

## 使用 AI 时保持主线的提示词

每次新对话先提供仓库位置和进度文件，再使用：

> 请先阅读 docs/LEARNING_PROGRESS.zh-CN.md 和 docs/LEARNING_ROUTE.zh-CN.md。只教我当前阶段，不替我跳级。先让我预测当前实验结果，再解释相关函数。新术语每次最多三个，每个必须绑定本仓库具体函数、输入输出和单位。区分代码事实、你的推断和模型假设。不相关概念放入待学列表。不要在教学中擅自修改源码。最后让我用自己的话复述，并给一道改变一个参数的迁移题；根据我的实际回答记录掌握证据，不能因为我说“懂了”就勾选完成。

保留一个主学习对话负责路线和进度。需要临时解释术语时，可以开一个短支线对话，但限定“只解决当前函数中的这个词”，结束后带回三句话：它是什么、影响哪个输出、回主线做什么实验。无需为每个新词再开长期对话。

结束一次学习时，请 AI 将“学过什么、实际做过什么、还有什么没懂、下一步是什么”写入进度文件；先检查它没有把未做过的实验标成完成。开始下一次时重新读这个文件，不依赖 AI 记得旧聊天。

## 怎样判断自己真正理解了

对每个阶段都做三件事：不用 AI 复述输入到输出；在运行前预测改变一个参数的影响；故意制造一个边界条件并解释测试为何通过或失败。卡住时回到相应函数，而不是继续收集术语。

你现在最适合从阶段 0 或 1 开始。第一道问题只有一句：**这辆车以 20 m/s 行驶，松开油门后，加速度应该是正、零还是负？证据在代码哪一行？**
